# إشعارات البريد في Pure Table

تستخدم المنصة Resend بطريقتين:

- رسائل حسابات الأعضاء (التفعيل، الدعوة، الرابط السحري، استعادة كلمة المرور، تغيير البريد، وإشعارات الأمان) تمر عبر Resend SMTP من إعدادات Supabase Auth.
- رسائل النماذج ترسل من الخادم عبر Resend API فقط؛ لا يُكشف المفتاح للمتصفح.

المرسل هو `PureTable <no-reply@puretable.co>`، وتنبيهات الإدارة تصل إلى `info@puretable.co`. جميع القوالب عربية، RTL، وتستخدم رابط الشعار الموحد `/api/public/brand-logo` حتى يتبع شعار الموقع المنشور.

| الحدث                            | إلى الإدارة                       | إلى الزائر                          |
| -------------------------------- | --------------------------------- | ----------------------------------- |
| رسالة التواصل                    | تفاصيل الرسالة ورابط لوحة الرسائل | تأكيد الاستلام عند إدخال البريد     |
| قائمة الانتظار                   | البريد والمدينة والمصدر           | تأكيد الانضمام                      |
| تسجيل عضو أو استعادة كلمة المرور | —                                 | قالب Supabase Auth المخصص           |

يسجل جدول `email_deliveries` حالة كل رسالة (`pending` أو `sent` أو `failed`) ومعرّف Resend. مفتاح الحدث فريد ويُرسل أيضاً كمفتاح idempotency لمنع التكرار عند إعادة المحاولة. لا يستطيع الزوار الوصول إلى السجل، ويمكن للإدارة قراءته فقط.

متغيرات الخادم المطلوبة:

- `RESEND_API_KEY`
- `EMAIL_FROM`
- `EMAIL_ADMIN_RECIPIENT`
- `APP_URL`

لتطبيق SMTP والقوالب على مشروع Supabase مستقبلاً:

```text
node scripts/configure-email-provider.mjs
```

يتطلب الأمر مؤقتاً `SUPABASE_ACCESS_TOKEN` بالإضافة إلى المتغيرات السابقة، ولا يجب حفظه في المستودع.
